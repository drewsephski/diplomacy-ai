# Remediation of the independent review

This maps every finding in [`independent-review.md`](independent-review.md) to its fix and to the test that guards it. All verification used an isolated build (port 3012, a fresh temporary database, `OPENROUTER_API_KEY` set to an empty string). **No paid model call was made, and nothing here claims paid validation.** Live games in the tests are browser-side fakes. Sandbox games run on the isolated server for free. Each run request in a test stands for one phase, which in a live game is up to 7 × (rounds + 1) billed model calls.

## Root cause and design

The review's watch bugs had one cause. The decision to request a phase was spread across `App.tsx` conditions. Session identity was a persisted `watchingId`, and nothing tied a response, a timer, or a pause to the session that started it. The fix replaces that with a single owner:

- **`src/watch/useWatch.ts` is the only code that sends `POST /run`.** A session is created only by an explicit press (Start game, Resume game, Resume at latest, Continue watching, Play next phase). It covers one match and has a token. `stop()` clears it unconditionally, so a response, poll, or timer that carries an old token is ignored and can never continue or restart it.
- **`src/watch/decide.ts` is a pure decision**, with unit tests (`tests/watch.test.ts`): wait while a request is in flight or the server is running, hold a guided phase until the viewer continues, then stop at a winner, the limit, or an error.
- **Every run carries a ticket, and the pause carries the same ticket** (`server/simulation.ts` `pauseMatch` / `startMatch`, `server/index.ts`). A pause that reaches the server before its run cancels that run (HTTP 409, no phase). A pause after it sets `job.pause`, which the engine checks between model calls, as before. When a late run response arrives for a session that already ended, the client sends the pause again for the job that now exists. *Pausing…* lasts until the server reports the game idle.
- **`holdWatch()` in `App.tsx` is the one way automatic play stops.** It is called by Pause, every dialog, every tab other than Watch, `visibilitychange` to hidden, seeking, the Guided view toggle, closing the guide, turning guidance off, and every switch of game. It ends the session and the free replay timer, and pauses the server if this page may have started a phase.
- **Recorded playback is separate from live generation.** A replay (guided popups or the timer) is offered wherever the viewer is not at the latest moment of an unfinished game of their own, and it never sends a run request. Only the latest moment of an unfinished game offers Start or Resume.

## Remaining limits

- **No paid validation.** The guided hold, the pause race, and the error paths are verified with sandbox games and browser-side live fakes. A real provider's latency was not exercised; the ticket logic does not depend on it.
- **A sandbox phase cannot be interrupted once its run starts.** Its negotiation and orders are computed synchronously before adjudication, so a pause that arrives after the run has reached the server still lets that one phase resolve. Live phases check `job.pause` between model calls, as before. A pause that arrives before the run is always honoured (ticket).
- **Model calls already sent are not cancelled.** Pause stops after the current model call settles (up to its 120-second timeout); the transport is not aborted. The UI shows *Pausing…* for that time.
- **If the server becomes unreachable during *Pausing…*,** the button stays on *Pausing…* and the banner explains the lost contact; the page cannot confirm the pause until the server answers.
- **Rapid opens from History** are also prevented in the UI (rows are disabled while a game loads); the navigation guard is tested through the welcome card's sample link instead. The delayed *extend* and *parent* responses are guarded in code (navigation id and match id) but have no dedicated browser test, because the UI keeps those controls busy while they load.
- **The mobile sheet** covers the lower half of the screen; the map shows above it. On very short landscape phones the map area above the sheet is small. Browser checks use Chromium only, with no screen-reader pass.
- **The fake live records** reuse the sample's checked phases; they test the client's controls, not live gameplay.
